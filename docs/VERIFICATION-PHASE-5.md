## Improvements and defects corrected

- **Evidence consistency:** importing a repository no longer reselects previously excluded evidence. Saved editor details load automatically; a saved source replaced by a newer resume is excluded with an explanation rather than producing an invalid selection on save. Slow imports reject a stale draft revision instead of overwriting newer work.
- **Repository management:** remove an individual repository from the draft without deleting the profile or activity. Saved/private and published snapshots stay unchanged until the developer explicitly reviews/saves/publishes. Canonical URL checks allow refreshing an existing repository at the four-repository limit.
- **Publication editing:** existing excerpt selections are restored on reload, and the saved source revision identifies whether the published details are current. Copy-link has visible success/error feedback. A private draft can expire before a publication; owners can now still reach Unpublish in that state. The browser check simulated expiry by aging only the synthetic QA workspace file; an automated test verified actual owner revocation after expiry.
- **Answer quality:** ordinary factual answers omit unsolicited interview-question paragraphs unless the latest request asks for suggestions. Explicit question-suggestion requests still work. Facts retain exact quote checks and a separate grounding audit; uncertainty remains distinct from supported facts. Skill-list support uses complete entries rather than substring matches.
- **Provider reliability:** one transient gateway/network retry shares the same total 55-second deadline. Quota, authentication and invalid model outputs are not automatically retried. Job-matching client/server time budgets accommodate generation, audit and one correction attempt.
- **GitHub quota option:** optional `GITHUB_TOKEN` stays server-only and is sent only to the fixed GitHub API origin with redirects rejected. Private repositories remain rejected. A rejected token receives actionable configuration feedback.
- **Voice resilience:** recognition construction, playback and cancellation exceptions preserve text input. Existing start/stop, mute, interrupt, processing and lifecycle behavior remains covered by tests.
- **Reports:** a shared deterministic helper derives up to five follow-ups from actual unresolved recorded questions; both the UI and PDF use it. No new candidate facts or hiring recommendations are generated. Report lists are numbered, public URLs wrap, PDF failures have a bounded timeout, and missing/error routes use the existing dark design.
- **Security/errors:** cross-site API reads cannot mint replacement private-owner cookies; public evidence remains readable without that side effect. Added framing/referrer/content-type/permission headers. Proxy HTML, malformed JSON and malformed resume uploads produce useful sanitized errors. PDF filenames are bounded before use.

## Environment, safety and deployment

Production needs a persistent Node 24+ host, HTTPS, `PROFILY_PUBLIC_BASE_URL`, runtime secrets and a persistent data parent.
